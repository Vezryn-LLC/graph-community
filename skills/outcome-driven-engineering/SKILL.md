# Outcome-Driven Engineering

- Identify the requested working result before building supporting machinery.
- Prefer the shortest complete vertical path and reuse normal Codex/native tools.
- Do not substitute plans, test totals, review reports or architecture for actual functionality.
- Fix ordinary defects during the task; don't turn every repair into a prerequisite campaign.
- Report what worked, how it was checked and any real blocker.
- Treat model calls, execution time and maintenance as engineering costs.
