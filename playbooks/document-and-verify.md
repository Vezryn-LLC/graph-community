# Document and Verify

**Use for:** documentation, runbooks, instructions, examples and policy edits.

1. Read the source of truth and intended audience.
2. Make the smallest accurate edit; remove competing obsolete instructions.
3. Verify referenced paths, commands and links when material; check Markdown structure.
4. Commit/publish with a concise description and update the relevant issue.

**Useful skills:** `outcome-driven-engineering`. A documentation change does not automatically need an independent reviewer or full test suite.
